# Website Builder · Motion Template Lite

已确认画面与声音：**v0.3**。Lite 工程版本：**1.0.0**。
**52 秒 · 1920×1080 · 30 fps · 1560 帧**。

先看 `preview/reference.mp4`：这是本工程自己的完整成片，随包压缩为 720p；源码导出 1080p。默认品牌 Page Studio 和六个示例网站用于演示。

本包保留完整可编辑源码、配置、必要照片与字体、已确认的混合音轨，以及一份成片预览。复现默认成片不需要 MCP 或 API key。首次安装依赖和渲染浏览器需要联网。

## 交给 Codex

用 Codex 打开解压后的整个文件夹，发送：

> 新产品是【产品名 / 官网】，素材在【目录，可选】。请阅读 README.md，观看 preview/reference.mp4，并检查配置和源码。将这套模板适配成该产品的完整发布视频。保留明亮网页界面、微弱紫色边缘光、编辑器的连续微距运镜、少量黑底品牌段和大字重音，以及快切、速度曲线、blur 和音画落点。根据产品真实工作流重写可能的成果 → 进入编辑器 → 选择组件 → 修改属性 → 看见结果 → 发布。保留同一对象的前后连续性、准确的鼠标落点和先点击后变化的因果。开头每次快切展示不同的真实成果类型，最后一个成果接到下一镜。UI 用代码提炼关键元素；不要每镜添加标题、说明小字或角落 Logo。同步替换品牌、配色、样例内容和产品主张。优先在现有源码上修改，最终交付完整 MP4 和可编辑工程。

只提供产品名也可以开始；同名产品请给官网。适配应基于可确认的功能，不要保留新产品没有的能力。也可以注明“借鉴视觉和 motion 方法，按新产品逻辑重新编排”。以本包成片与源码为依据，无须另带第三方参考片。

## 适合什么产品

适合网站构建器、无代码编辑器、设计工具、落地页或新闻通讯工具，以及通过“选择 → 编辑 → 实时结果”证明价值的创作产品。

这是表达逻辑，不是通用功能清单。若产品是对话生成器，应把具体操作改成交流需求与结果修订；不要仅替换名字却继续展示无关的网站控件。

## 安装、逐帧查看与导出

需要 Node.js 22+。默认导出使用锁定版本 Remotion 自带的 FFmpeg，无需系统 FFmpeg。

```sh
npm ci
npm run check
npm run studio
```

在 Studio 中选择 `WebsiteBuilder`，可以拖动时间轴逐帧检查。

```sh
npm run render
```

输出 `dist/website-builder.mp4`。默认并发 2；内存不足时可用 `RENDER_CONCURRENCY=1 npm run render`。

```sh
npm run stills -- --frames=38,44,50,56,63,68,95,396,446,631,783,1327
```

关键帧写入 `dist/frames/`，同名 PNG 会覆盖。`preview/reference.mp4` 只供观看，不参与渲染；全片从本包源码和素材独立生成，不依赖以前的版本或本地服务。

| 实际输出时间与设计时间映射 | `config/beat-alignment.json` |

| 六个不同的开头网站 | `src/WebsiteShowcase.tsx` |
| 编辑器、页面、控件和图标 | `src/UI.tsx` |

品牌配置是主要入口；网页品牌、样例文案、Logo 图形和部分颜色仍在源码中。`accent` 不会自动重配六个示例网站，也不会改写照片、功能或所有文本。完整换品牌时一起检查这些内容。

照片在 `public/photos/`，下载来源在该目录的 `sources.json`。Geist 已附本地字体和许可。衬线部分使用系统 Georgia；缺少 Georgia 的系统需提供适用的本地衬线字体并核对版式。其他语言需包含相应字形的字体，同时检查换行、宽度和阅读时间。

## 必须保留的设计方法

每镜只有一个核心动作。大字只在主张和转折处强调；多数信息由产品操作和结果直接表现。不要每镜固定一套“标题 + 两栏卡片”结构。

开头六个网站分别是旅行、建筑、音乐、作品集、户外社区和新闻通讯。每个只出现一次，用版式、画面主体、字体形状和色块形成明显差异；最后的 Fieldnotes 正是下一镜组装的网页。

保留对象身份：飞入卡片就是最终网页里的同一张卡片，归位后 transform 回到正常布局，不通过淡入另一套静态元素掩盖落点。缩放或倾斜时，鼠标和控件共用同一相机坐标，避免鼠标脱离目标。

界面状态顺序：鼠标到位 → 按下反馈 → 松开 → 结果变化。颜色示例保持同一区块与照片不变；表单变化同时展示设置和结果，理解后再放大结果。运镜必须有明确关注点。

跨场运动与阅读停留分开安排。主要运镜通常约 0.45–0.8 秒，组件约 0.3–0.55 秒，按位移和信息量调整。不要所有运动套同一个 spring，不用循环漂移填满停顿。

`src/motion.ts` 的 arrive `[0.16,1,0.3,1]`、travel `[0.76,0,0.24,1]`、depart 和 focus 各有用途。曲线之外还要一起看距离、时间、落点和重叠。大字逐字聚焦；运动 blur 从相邻时刻位移估算，在落点收清。blur 用来交代速度与景深，不要让阅读画面长期模糊。

### 两种时间坐标

`beat-alignment.json` 的 knots 是 `[实际输出秒, 设计秒]`；`Film.tsx` 把输出帧 / 30 转成设计时间，再驱动场景。场景代码和 `interactions.json` 用设计秒。声音使用实际输出时钟。

例如设计 17.4 秒对应实际 17.3 秒；设计 23.75 秒对应实际 23.8 秒。不要直接把内部设计时间当成音轨时间。第一轮适配保留 52 秒和关键落点；改时长需同步调整所有场景、阅读窗口、音乐和 SFX。

## 声音

Lite 仅包含 `public/audio/master.m4a`，是已确认 v0.3 成片的 AAC 原音频流，包含生成的器乐 BGM 与动作 SFX，**没有旁白**。完整导出先渲染画面，再接入一次 master，默认不叠加第二条音轨。M4A 直接复制音频流，其他格式编码 AAC。

复现基线无需生成声音。若调整动作位置或总时长，需同步重混，不能只移动画面。`audio-cues.json` 是落点记录，编辑它不会自动重混；本包没有独立分轨。重混时使用自己的音频工具，或向提供者索取完整版本的分轨。新 master 放入 `public/audio/` 并更新品牌配置。`audio.mode` 可设为 `mute`。

BGM 保持连续；重音跟随主要动作，而不是给每个小元素都加音效。短点击对应按下，发布成功音在结果出现后。更换音乐时先测量拍点，再调整镜头，不要认为相同 BPM 就会自动对齐。

## 交付

先确认默认基线能够完整渲染，再进行产品适配。检查快切差异、组装落点、点击先后、文字清晰度、跨场连续性、声音落点及片尾。修改要合入完整视频，交付 MP4 与修改后的工程。

素材来源见 `ASSETS.json`；完整性校验见 `manifest.json` 和 `SHA256SUMS.txt`。本包不含历史对比页、原作者影片、分轨、安装依赖、服务凭据或渲染工作文件。
