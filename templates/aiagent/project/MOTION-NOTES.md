# 动效说明与编辑方法

本版的顺滑感来自镜头速度、焦点位置、错峰进入和收势的共同设计。60 fps 提供更密的时间采样；贝塞尔曲线决定物体如何起步、经过中间点并停稳。提高帧率本身不会补足这些运动设计。

## 时间单位

`src/index.tsx` 使用实际的 60 fps 全片帧号；场景内调用 `useFrame30()`，以 30 fps 时间单位编写关键点，再按实际帧率采样。例如场景局部 `f = 30` 表示该场景开始后 1 秒，对应 60 个输出帧。新增场景动画时沿用这一约定，避免把时长缩短一半。

| 场景 | 全片帧范围（包含两端） | 起始秒 |
|---|---:|---:|
| Opening | 0–263 | 0.00 |
| TypeSequence | 264–477 | 4.40 |
| Voice | 478–707 | 7.97 |
| PromptDemo | 708–939 | 11.80 |
| Montage | 940–1057 | 15.67 |
| Claims | 1058–1399 | 17.63 |
| Outro | 1400–1687 | 23.33 |

## 贝塞尔、错峰与收势

- **缓动曲线**：`src/common.tsx` 中 `CURVES` 和 `curve()` 控制一段运动的快慢分布。`enter`、`glide`、`depart`、`settle` 等名称表示用途，可分别调整，避免所有元素同速起停。
- **连续镜头轨迹**：`cubicTrack()` 以及部分场景的局部 `track()` 把位置和节点速度转换为三次贝塞尔控制点。相邻段共用节点速度，使镜头经过中间关键点时保持运动；需要停住时才把速度设为零。它保证轨迹内部的速度连续，不代表每个场景切点的加速度也连续。
- **错峰进入**：逐字、逐卡片延迟让观众先看到主体，再读到细节。延迟通常只差少量 30 fps 时间单位；长文字应检查最后一个字是否仍有足够停留时间。
- **收势与回弹**：通过预压、短暂过冲和回到最终值完成按钮及图标反馈。幅度要与物体大小匹配，停稳后保留阅读时间。
- **速度模糊**：镜头或图标运动越快，模糊越明显，并设有上限。它是代码驱动的 CSS 模糊近似；停稳时应恢复清晰。

## 各段的调整入口

| 文件 | 可直接调整的运动 |
|---|---|
| `src/common.tsx` | 共享贝塞尔手柄、`cubicTrack()`、速度估计和基础图形 |
| `src/scenes/Opening.tsx` | `cameraTrack()` 的位置与速度；software 从代码中接管的坐标、弧线、光扫；UI 卡片的深度与延迟 |
| `src/scenes/TypeSequence.tsx` | 文字切换、星号旋转、Code 字形过渡、放大与退出 |
| `src/scenes/Voice.tsx` | `zoomKeys`、`cameraKeys`；光标曲线、麦克风预压回弹、波形展开和横移 |
| `src/scenes/PromptDemo.tsx` | `scaleKeys`、`cameraXKeys`、`cameraYKeys`；光标轨迹、提示词替换、提交按钮回弹和放大转场 |
| `src/scenes/Montage.tsx` | 镜头与产品卡片的位移、旋转、缩放和错峰 |
| `src/scenes/Claims.tsx` | 圆盘展开、逐字呈现、图标沿文字移动、终端符号出现和图标收势 |
| `src/scenes/Outro.tsx` | 背景缓慢移动、品牌标题收束、片尾标语逐词进入 |

## 修改后的检查重点

先在 Studio 中循环查看改动段，再用 `npm run render -- --range=起始帧-结束帧` 检查实际输出。检查镜头的视线焦点是否连续、文字是否读得完、动作在节拍上是否停稳，以及转场前后是否出现无意的跳位。静帧用于检查布局，视频用于判断速度。

开场 software 抽离坐标按 Menlo 字宽设计，跨系统字体回退可能影响衔接。若主动换字体，需同时检查 `Opening.tsx` 的字符步进和抽离锚点。

已确认的音轨与时间线保持原样；编辑曲线时可先保留总时长和场景边界，通过内部关键点调整动作节奏。
