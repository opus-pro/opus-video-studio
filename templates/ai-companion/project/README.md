# AI Companion · Motion Template Lite

已确认画面与声音：**v0.12**。Lite 工程版本：**1.0.0**。
完整成片为 **30 秒 · 1920 × 1080 · 30 fps · 900 帧**。

先看 `preview/reference.mp4`。它是这套工程自己的完整演示成片，随包压缩到 720p；源码仍导出 1080p。默认产品 Companion、角色 Pip 和示例域名都是虚构身份。

本包保留可编辑源码、品牌配置、字体、批准的混合音轨和一份成片预览。没有历史版本、独立声音分轨、原作者参考影片、node_modules 或服务凭据。复现基线不需要 MCP 或 API key。

## 交给 Codex

用 Codex 打开解压后的整个文件夹，发送：

> 新产品是【产品名 / 官网】；我的素材在【目录，可选】。请阅读 README.md，观看 preview/reference.mp4，再检查配置和源码。将这套模板适配成新产品的完整 30 秒发布视频。保留现有视觉风格、角色与场景的连续运动、曲线、blur 和声音节奏；根据新产品的真实功能调整角色、对话、演示操作和结果内容。同步替换品牌、配色、网址与旁白。优先复用源码，最终交付完整 MP4 和修改后的工程。

仅提供产品名也可以开始；同名产品请给官网。自己的 Logo、角色图或产品素材能帮助保留品牌特点。不能确认的功能，先确认再写进影片。

若只想学习风格而不是直接换品牌，可明确写“借鉴本包的视觉和运动方法，按产品逻辑重新编排”。仍以本包成片和源码为依据，不引入第三方原片。

## 适用的产品逻辑

适合角色陪伴、带长期记忆的聊天、个性化助手，以及把交流变成共同创作或分享体验的产品。
默认结构是：发现角色 → 开始交谈 → 用具体回复证明记忆 → 个性与声音 → 共同创作 → 分享与参与 → 品牌。

这是表达结构，不是必须硬套的功能清单。产品没有记忆、角色定制或社交分享时，改成它真实的价值证明。例如工作助手可以用“记住项目背景 → 给出有上下文的建议”；不能仅改名却保留不存在的功能。
同一产品的 UI 与结果必须相互对应。片中月球列车是程序化绘制的示例结果，换产品时需要按真实产出重新设计，不会自动生成新的内容。

## 安装、逐帧查看与导出

需要 Node.js 22+。首次安装依赖与渲染浏览器需要联网。

```sh
npm ci
npm run check
npm run studio
```

Studio 选择 `Companion`，可拖动时间轴逐帧查看。
完整导出：

```sh
npm run render
```

输出为 `dist/companion.mp4`。检查关键帧：

```sh
npm run stills -- --frames=6,87,93,332,410,622,767,899
```

图片输出在 `dist/frames/`。重新检查改过的帧前，删除对应的旧 PNG，脚本会跳过已存在的图片。
默认渲染并发 2；内存不足时使用 `RENDER_CONCURRENCY=1 npm run render`。
`preview/reference.mp4` 只供观看，不参与后续渲染；所有画面由 `src/` 和 `public/` 生成。

素材放在 `public/`，配置填写相对于它的路径，不用机器绝对路径。
`portraits` 的六个空字符串默认使用代码角色；提供自己的图片路径后，会改用对应图片。
`accent` 控制部分主题色；角色、环境、界面中还有直接写在场景源码里的颜色，完整换色需要一起检查。
默认字体适配英文。改成中文或其他文字时，添加包含相应字形的本地字体，并检查宽度、换行和阅读时间。
不要假设只换名称就能完成所有产品适配。

## 必须保留的设计与 motion 方法

每个画面有一个核心主体。角色、消息或正在生成的作品直接讲故事；大字只在主张、强调或转折处出现，可以位于主体背后。不要每段都添加标题、说明小字、左上角 Logo，或变成“左标题右 UI”的展示页。

保持有前后距离的角色世界、通透边缘、柔和但有对比的环境光，以及暖色人物和青绿空间的关系。换主题色时保留层次和对比，而不只是全片套一个滤镜。

让同一个对象承接前后动作：角色进入聊天头像，设备表面承接选择与输入，提示提交后变成结果，同一件结果被分享，再扩展为更多参与者。通过靠近、传递、展开和尺度变化衔接，不把每段拆成独立淡入淡出的页面。UI 提炼关键元素用代码画。

消息顺序必须有因果：昨天的具体信息 → 角色主动问起 → 用户意识到它记得。说话者左右位置不跳变；输入和回复先给足阅读时间，再快速移动。不要为了节奏把打字过程压到看不清。

区分可读停留与快速位移。主要跨场运动集中在约 8–14 帧，小元素约 10–16 帧；这些是当前风格的起点，实际需结合位移和信息量判断。不要给每个元素同一持续时间、同一 spring，或用循环漂移填满停顿。下一场在当前对象经过注意力中心时接入，运动可以重叠。

曲线在 `timeline.curves`：
- arrive `[0.12, 0.84, 0.20, 1]`：快速到达，短收尾。
- travel `[0.50, 0.02, 0.16, 1]`：跨场传递的加速和制动。
- focus 与 depart：聚焦、退出，按用途选择。

曲线不是质量开关；距离、时长、对象关系和落点共同决定速度感。空间曲线与时间曲线分开控制。人群共享镜头参数、保留邻接关系，不让背景角色穿过主角。

每种 blur 有明确职责：大字约 20px → 0 的逐字聚焦；角色和界面随位置、旋转、缩放速度产生运动模糊；背景用景深降低干扰。运动 blur 由相邻帧采样估计。主要 UI 与文字在可读停留时要清晰，不能给整片永久加模糊。

### 两套时间坐标

输出固定 900 帧 / 30 秒。绘图代码保留原来 960 帧的创作坐标，由 `src/clock.ts` 和 `timeline.timeMap` 映射到实际成片。
`timeMap` 每项是 `[输出帧, 创作帧]`。例如创作帧 664 对应输出帧 622，约 20.73 秒；创作帧 827 对应输出帧 767，约 25.57 秒。
旁白和混音运行在实际 30 秒时钟。不要把 TSX 内部帧数直接除以 30 当成成片时间。
第一轮迁移保持全长和关键落点；如果必须更改时长，画面、阅读时间、旁白、音乐和 SFX 要一起调整。

## 声音与迁移

Lite 仅含 `public/audio/master.m4a`，内有已认可的新 BGM、英文旁白及动作 SFX。
重现默认成片不需要调用模型。换品牌或产品内容时，必须同步换旁白和完整混音；本包不含独立音乐、旁白或音效分轨。
需要重混时，使用自己的音频工具生成分轨，或向包的提供者索取完整版分轨。原旁白不能充当新品牌的最终配音；工具未连接时说明声音尚未适配。

社媒音乐的默认方向是第一拍给出身份，前 3 秒已经有鼓、低音和旋律钩子，避免先慢后快的长引子。后续靠密度变化、短暂收住和再次释放形成反差。检查实际生成结果的开头，不能只相信 prompt。
当前曲目重新生成后剪去约 0.92 秒引子，以首个有力鼓点开场，末尾给最后一句旁白留空间。生成目标 140 BPM 不等于实测 BPM；旁白保持自然语速。

音效不平均分配：主要展开有重音，小操作更轻，记忆回复可用音乐收弱来突出。
SFX 起音可以提前，感知峰值落在动作到位处。保持同一条 BGM 连贯，避免剪辑拼接造成断层。
`audio-cues.json` 中的瞬态是测量候选，音效落点是混音记录；改 JSON 不会自动重新混音。
新混音放到 `public/audio/`，更新 `brand.audio.master`。也可以把 `brand.audio.enabled` 改为 false 先做无声视觉。
最终导出使用 Remotion 自带的 FFmpeg 接入混音；默认 M4A 直接复制音频流。默认只播放 master，不能重复叠加。

## 完成交付

先运行默认基线，再适配产品。正常速度看完整片，并检查关键转场前、中、后的几帧：文字裁切、对象相撞、消息因果、速度尾巴、blur 收清、音画对应和最后一秒。
所有修改放进完整 MP4，交付视频与修改后的工程，注明仍未适配的部分。
`manifest.json` 记录包内文件的校验值。来源及字体许可见 `ASSETS.json` 和 `public/fonts/`。
